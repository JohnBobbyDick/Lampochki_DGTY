## С чего начать

1. Прочитать `tgprompt.md` (блоки B, C1, C2, D и «Готово, когда») и этот файл.
2. Выполнение — subagent-driven (`superpowers:subagent-driven-development`): по задаче — исполнитель, ревью,
   цикл исправлений, затем повторное ревью.
   - Рабочая папка плана: `.superpowers/sdd/tgprompt/` (в `.gitignore`). Журнал — `progress.md`: в нём таблица
     предварительной проверки, решения (`Ruling:`) и строки `Task X: complete`. Готовые задачи заново не запускать.
   - Брифы уже лежат там: `task-B-brief.md`, `task-C1-brief.md`, `task-C2-brief.md`, `task-D-brief.md`. Отчёт
     исполнителя — `task-<X>-report.md` рядом с брифом. Пакет для ревью — скрипт `review-package tgprompt.md BASE HEAD`.
   - Если папку стёрли (`git clean -fdx`), брифы извлекаются заново из `tgprompt.md`, а состояние — по этому файлу
     и `git log`.
3. Следующая задача — **B** (B1–B5 одним исполнителем, одна задача на ревью). BASE = текущий HEAD.
4. Порядок дальше: B → C1 → C2 → D → финальное ревью (самая сильная модель) → одна волна исправлений → повторное
   ревью → обновить `CLAUDE.md`, `docs/architecture.md`, `README.md` → отметить пункты в `tgprompt.md` → обновить
   этот файл.
5. После каждого блока отмечать `[x]` в `tgprompt.md` и коммитить. Пользователь может попросить остановиться
   после блока — тогда следующий не начинать без команды.

## Отложено (не блокирует)

Из плана tgprompt.md:
- A1:
  - тест сверки `docker-compose.yml` пропускается без PyYAML — можно переписать на регулярные выражения;
  - тест импортирует приватный `uvicorn._TrustedHosts`;
  - при параллельных 409 `/parse` отправляется дважды (две единицы лимита, без цикла);
  - очистка счётчиков по IP идёт под блокировкой;
  - нет теста запасного `Math.random` в `utils/sessionId.ts`;
  - `api/ai.py:106` дважды вызывает `state.current()`.
- A2:
  - зависимости эффекта в `useSync.ts` и отбрасывание запоздавших ответов не покрыты тестами (нет тестов хуков);
  - нет теста передачи ошибки `getGraph` и отрисовки текста пустого графа;
  - при ошибке разбора в сторе остаются старые `ast`/`methods`.
- `docker compose up` вживую не проверялся: Docker на этой машине не запущен.
- `docker compose config` при ревью вывел ключи Gemini и данные прокси из `backend/.env` в журнал сессии — при
  необходимости заменить ключи.

С этапа 7:
- README.md:77-79: пункт про лимит сессии 10 с вставлен над строкой-продолжением пункта «Запуск».
- `/api/ai/fix` угадывает язык по тексту, если в запросе нет `language`; `_generate_patches` по умолчанию `java`.
- Глубокая цепочка вызовов (~300) → `RecursionError` в `analyze_ast`.
- Парсер Python: `case (\n 1|2\n):` теряет `case (`; def внутри верхнеуровневого `if`/`try` называется
  `main.helper`; одинаковые вложенные def дают одинаковые id; правка заголовка с `\` слегка сдвигает отступ.
- CFG: у `while True` есть выход `else`; `return` в `try` идёт мимо `finally`.
- Дефекты: правило конкатенации не учитывает порядок присваиваний; имена из строковых аннотаций считаются
  неиспользуемыми импортами.
- Декомпозиция Python: меняется `__module__` перенесённого класса; `from m import *` ставится в начало модуля; в
  `main.py` остаются лишние импорты; нет пустой строки после добавленных `from x import`.
- Покрытие Python: нет проб на `async for`, `if` в comprehension, guard в `match`, `assert`; `elif` подписан как
  «if»; тело класса считается в объемлющем контексте; генератор засчитывается на первом `next()`;
  `KeyboardInterrupt` → код 1; `_loader_main` не используется; соседние модули могут затенить stdlib-импорты
  загрузчика; порядок проб в docker сверяется только по числу слотов; ошибка записи в `prepare_python` оставляет tmp.
- Java: если в `Cov.java` не удаётся mmap, покрытие молча показывает 0%.
- Java-консоль в docker — `-Xmx256m`, локально `-Xmx100m` (одна константа в `runner.docker_command`).
- Тесты: предупреждение Starlette TestClient; `dataclasses.replace` ничего не делает; голый `return` вместо skip в
  тесте symlink.
- `calculator.py`: константа `OPERATORS` не используется.
