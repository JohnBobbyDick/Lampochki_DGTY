# Java Blueprints

Визуализатор и анализатор Java-кода: редактор ↔ граф (CFG / Call Graph / Class Diagram), диагностика
и Big O, обратная генерация кода из графа, декомпозиция монолита, запуск с Quality Gate.

## Запуск через Docker

```bash
docker compose up --build        # UI: http://localhost
```

## Локальная разработка

```bash
# backend (Python 3.11+, нужен JDK 11+ в PATH)
cd backend && python3 -m venv venv && source venv/bin/activate
pip3 install -r requirements.txt
uvicorn main:app --reload --port 8000
python -m pytest                 # тесты

# frontend
cd frontend && npm install && npm run dev   # http://localhost:3000, /api проксируется на :8000
```

## Как пользоваться
1. Загрузите `.java` (кнопка или drag-n-drop) — либо правьте код в редакторе, граф обновляется через 500 мс.
2. Наведите курсор на строку ↔ узел графа; клик по узлу переносит курсор в редактор.
3. Двойной клик по узлу CFG → правка текста → Enter → код метода перегенерируется.
4. **Run** (Ctrl+Enter) — запуск в интерактивной консоли внизу (WebSocket): вывод идёт потоком, ввод для
   `Scanner` набирайте прямо в консоли; Stop/EOF — кнопки.
   **Сравнить** открывает вкладку «Сравнение»: предыдущий и последний запуск этого файла (хранятся 2 последних
   на файл, в памяти) со статусами (исключение, таймаут, остановка, лимит вывода) и пометкой «Ввод отличался»,
   если ввод был другой. Ошибки компиляции в историю не попадают.
   **Decompose** (Ctrl+D) — предложение файлов, Quality Gate и zip. Результат Quality Gate — в панели «Декомпозиция»
   и во вкладке «Проверка» (открывается автоматически). «Проверить поведение» правки ИИ — во вкладке «Проверка»,
   сравнивает вывод с исходным кодом.
5. Undo/Redo: Ctrl+Z / Ctrl+Y.
6. Скачивание: иконка у вкладки активного файла скачивает его; «Скачать изменённые» в дереве проекта собирает
   zip только из изменённых файлов.

## Покрытие кода
После **Run** (интерактивная консоль) считается покрытие: строки, методы, ветви решений (`if/while/for/do/?:`),
условия (каждое элементарное условие в `&&`/`||`/`!`) и реляционные исходы сравнений.
- **Где видно:** цветные полосы в gutter редактора (зелёная — выполнено, красная — нет, жёлтая — частично;
  при наведении — число выполнений и непройденные исходы) и вкладка «Покрытие» внизу (проценты по файлу и методам,
  список непройденного с переходом к строке).
- **Накопление и сброс:** покрытие суммируется по запускам одного и того же текста файла. Любая правка кода
  сбрасывает его насовсем (вкладка просит запустить снова); есть кнопка «Сбросить покрытие». Данные не теряются
  при Stop, таймауте и kill.
- **Ограничения:** пробы ставятся только в решениях `if/while/for/do/?:` (`boolean ok = a < b;` не
  инструментируется). У `==`/`!=` два исхода (`==`/`!=`), у `<`, `<=`, `>`, `>=` три (`<`, `==`, `>`).
  `case`-группа и `catch` считаются одним исходом «выполнен»; проваливание (fall-through) в следующую
  `case`-группу отмечает и её. У константных `while (true)`/`for (;;)` нет пробы ветви.
  Если код не удаётся разобрать для покрытия или инструментированный код не компилируется, программа
  запускается без покрытия, а панель показывает причину. Пакетные запуски (Quality Gate, проверка декомпозиции)
  не инструментируются. Покрытие Python и C++ появится на этапах 7–8.

## Ограничения
- Сервер хранит последний разобранный код в памяти (демо на одного пользователя).
- Парсер — `javalang` (Java ≤ 8 синтаксис; без records/switch-выражений/var в лямбдах).
- Декомпозиция переносит только `static`-методы; вложенные static-классы становятся файлами.
- Правка узла графа поддерживает текст операторов, условий циклов/if, return/throw, catch-параметры.
- Запуск Java: `JAVA_SANDBOX_MODE=subprocess` (по умолчанию, таймаут 10 с, `-Xmx256m`) или `docker`
  (изоляция без сети, 256 МБ).

## AI-подсказки (Gemini, опционально)
```bash
cp backend/.env.example backend/.env   # LLM_ENABLED=true, ключи и прокси — см. комментарии в файле
```
- **«Объяснить с ИИ»** у дефекта — объяснение и исправленный фрагмент (если применим); иконка «Совет ИИ по разбиению»
  во вкладке «Декомпозиция».
- **Диагностика** всегда отражает текущий код: подсказка, чей фрагмент исчез, скрывается сразу; авто-ревью отменяет
  запрос при новой правке; ответ «Объяснить»/«Исправить» не отбрасывается, но его правка скрывается, как только её
  фрагмент пропадает из кода. Ошибки `javac` с номерами строк — в разделе «Синтаксис и компиляция», у каждой кнопка
  «✨ Исправить с ИИ» (при включённом ИИ). Если `javac` отработал, показываются только его ошибки (он главнее
  парсера); ошибки парсера видны лишь когда `javac` не запускался, и без кнопки ИИ.
- **Авто-ИИ:** через 5 секунд после последней правки кода показывается плашка «ИИ-модель смотрит, как улучшить ваш
  код…», затем в шапке появляется кнопка «✨ N идей» → панель с советами (клик по совету — переход к строке).
  Новая правка сбрасывает таймер и отменяет запрос. Отключается галочкой «Авто-ИИ» (запоминается в браузере).
- **Ключи:** `GEMINI_API_KEY=k1,k2,k3` (список через запятую); `GEMINI_KEYS_COUNT` — использовать только первые N.
- **Прокси:** `GEMINI_PROXIES=ip:login:password,ip:port:login:password,…` — запросы к Gemini идут только через них
  (случайный прокси на каждую попытку); протокол — `GEMINI_PROXY_SCHEME` (по умолчанию `auto`: порт «обнюхивается» без отправки пароля — ответ `0x05` значит SOCKS5, `HTTP/…` значит HTTP — и найденный протокол запоминается; если порт молчит, на следующих попытках перебираются `http` → `socks5` → `https`; можно зафиксировать `http`/`https`/`socks5`/`socks5h` или указать схему прямо в записи `socks5://…`); для записей без порта —
  `GEMINI_PROXY_PORT`. Без прокси соединение прямое.
- **Ретраи:** при ошибке (сеть, 4xx/5xx, пустой или неразборчивый ответ) запрос повторяется с другим случайным ключом
  и прокси; модель облегчается (`GEMINI_MODEL` → `gemini-2.5-flash` → `gemini-2.5-flash-lite`, список —
  `GEMINI_FALLBACK_MODELS`); пауза между попытками 2, 4, 6… с. Число попыток — `GEMINI_MAX_RETRIES` (по умолчанию
  число ключей, максимум 5). Когда ключи кончились, список начинается заново.
- **Применимые правки:** модель возвращает пару «фрагмент → замена» (+ недостающие `import`). Сервер находит фрагмент
  в коде (отступы не важны, место должно быть однозначным), расставляет отступы и проверяет результат (синтаксис +
  `javac`, ничего не запускается). Пользователю показывается только правка, которая не добавляет новых ошибок
  относительно текущего кода; для «✨ Исправить с ИИ» она также должна устранять целевую ошибку. Невалидные правки
  и советы без правки скрываются; если все правки невалидны, модель дважды переспрашивают с текстом ошибок.
  Кнопка **«Применить»** показывает diff; при применении проверка повторяется на актуальном коде (если вы успели
  править — фрагмент ищется заново). Ctrl+Z отменяет правку; «Проверить поведение» сравнивает вывод с исходным
  кодом (с вашим вводом из консоли).
- **Big O «было → станет»:** у каждой применимой правки ИИ сервер считает сложность затронутых методов до и после
  (`bigoBefore`/`bigoAfter`; затронут метод, чьи строки задеты правкой или чья оценка изменилась, например `main`,
  вызывающий исправленный метод). В строке «Сложность методов · Big O» и в просмотре правки показывается
  `O(n²) → O(n) · ~1000× быстрее`. Ускорение считается только по формуле, без запуска: `f_до(n) / f_после(n)` при
  n ≈ 1000 (тултип «при n ≈ 1000»), `log` по основанию 2; значение округляется до ближайшего (по логарифму) из
  2, 5, 10, 100, 1000, 10000, 100000, 1000000, всё выше — «>1000000×». Если несколько правок применимы одновременно,
  «после ИИ» — сложность после всех: непересекающиеся применяются по очереди, при пересечении строк берётся лучшая
  одиночная (`POST /api/ai/bigo-combined`, ИИ не вызывается). При той же сложности бейдж скрыт целиком (и стрелка, и ускорение); если
  стало хуже — красный бейдж «~N× медленнее»; при неизвестной сложности (`O(?)`) стрелки и ускорения нет.
- Без LLM кнопка «Объяснить с ИИ» даёт статические советы из базы паттернов, авто-ревью молчит. Все вызовы асинхронные.
- Диагностика: `cd backend && python check_llm.py` — по одному запросу через каждый прокси и напрямую (запускайте там,
  где будет работать приложение; в Docker: `docker compose exec backend python check_llm.py`). Если на компьютере
  включён VPN в режиме TUN, он перехватывает соединения и прокси с этой машины не проверить.
- SOCKS5: при `auto` определяется сам; принудительно — `GEMINI_PROXY_SCHEME=socks5` (`socksio` уже в `requirements.txt`).
- Локальная альтернатива: `LLM_PROVIDER=ollama`.
- Ключи и логины прокси не попадают в ответы API и логи (в логах — только `host:port` и последние 4 символа ключа).

## Безопасность
- Сервис выполняет присланный Java-код. В `subprocess`-режиме это **не песочница** — только для локальной разработки;
  для доступа извне используйте `JAVA_SANDBOX_MODE=docker`. Авторизации нет (демо на одного пользователя).
- Вызовы API и WebSocket принимаются только с разрешённых origin (`ALLOWED_ORIGINS`, по умолчанию localhost:3000
  и localhost) или с того же хоста, с которого отдаётся UI.
