# Java & Python Blueprints

Визуализатор и анализатор кода (**Java** и **Python 3.11+**): редактор ↔ граф (CFG / Call Graph / Class Diagram), диагностика
и Big O, обратная генерация кода из графа, декомпозиция монолита, запуск с Quality Gate.

## Поддерживаемые языки
- **Python (3.11+)** — встроенный парсер на базе `ast`, полный статический анализ AST, генерация CFG/Call Graph/Class Diagram, расчет Big O, детекция дефектов, декомпозиция модулей, запуск кода с интерактивной WebSocket консолью и Quality Gate.
- **Java (до 17)** — парсер на базе встроенного форка `javalang` (`backend/javalang/`, расширен до Java 17: record,
  `sealed`/`non-sealed`/`permits`, `switch` со стрелками и switch-выражения с `yield`, `instanceof` с образцом,
  текстовые блоки `"""`, `var`), компиляция через `javac` (в Docker — JDK 17) и выполнение в изолированной песочнице.
- Быстрый переключатель `[Java | Python]` в шапке приложения + автоматическое распознавание языка при загрузке `.java` / `.py`.

## Запуск через Docker

```bash
docker compose up --build        # UI: http://localhost
```

## Как пользоваться
1. Загрузите `.java` или `.py` (кнопка или drag-n-drop) — либо переключите язык в шапке и правьте код в редакторе, граф обновляется через 500 мс.
2. Наведите курсор на строку ↔ узел графа; клик по узлу переносит курсор в редактор.
3. Двойной клик по узлу CFG → правка текста → Enter → в исходнике заменяется только текст этого узла (остальной
   код и форматирование не меняются), затем код до и после правки автоматически запускается и сравнивается —
   вердикт во вкладке «Проверка».
4. **Run** (Ctrl+Enter) — запуск в интерактивной консоли внизу (WebSocket): вывод идёт потоком, ввод для
   `Scanner` (Java) / `input()` (Python) набирайте прямо в консоли; Stop/EOF — кнопки.
   **Сравнить** открывает вкладку «Сравнение»: предыдущий и последний запуск этого файла (хранятся 2 последних
   на файл, в памяти) со статусами (исключение, таймаут, остановка, лимит вывода) и пометкой «Ввод отличался»,
   если ввод был другой. Ошибки компиляции/синтаксиса в историю не попадают.
   **Decompose** (Ctrl+D) — предложение файлов, Quality Gate и zip. Результат Quality Gate — в панели «Декомпозиция»
   и во вкладке «Проверка» (открывается автоматически). «Проверить поведение» правки ИИ — во вкладке «Проверка»,
   сравнивает вывод с исходным кодом.
5. Undo/Redo: Ctrl+Z / Ctrl+Y.
6. Скачивание: иконка у вкладки активного файла скачивает его; «Скачать изменённые» в дереве проекта собирает
   zip только из изменённых файлов.

## Покрытие кода
После **Run** (интерактивная консоль) считается покрытие: строки, методы, ветви решений (`if/while/for/do/?:`),
условия (каждое элементарное условие в `&&`/`||`/`!`) и реляционные исходы сравнений.
- **Где видно:** цветные полосы в gutter редактора (зелёная — выполнено, красная — нет, жёлтая — частично;
  при наведении — число выполнений и непройденные исходы) и вкладка «Покрытие» внизу (проценты по файлу и методам,
  список непройденного с переходом к строке).
- **Накопление и сброс:** покрытие суммируется по запускам одного и того же текста файла. Любая правка кода
  сбрасывает его насовсем (вкладка просит запустить снова); есть кнопка «Сбросить покрытие». Данные не теряются
  при Stop, таймауте и kill.
- **Ограничения:** пробы ставятся только в решениях `if/while/for/do/?:` (`boolean ok = a < b;` не
  инструментируется). У `==`/`!=` два исхода (`==`/`!=`), у `<`, `<=`, `>`, `>=` три (`<`, `==`, `>`).
  `case`-группа и `catch` считаются одним исходом «выполнен»; проваливание (fall-through) в следующую
  `case`-группу отмечает и её. Ветка `case X ->` считается отдельно (без проваливания). Условие с образцом
  (`x instanceof Foo f`) проб не получает: обёртка вывела бы переменную `f` из области видимости. У константных `while (true)`/`for (;;)` нет пробы ветви.
  Если код не удаётся разобрать для покрытия или инструментированный код не компилируется, программа
  запускается без покрытия, а панель показывает причину. Пакетные запуски (Quality Gate, проверка декомпозиции)
  не инструментируются.
- **Python:** те же метрики и тот же интерфейс. Ветви — `if/elif/while`, тернарный `x if c else y`, `for`
  (исходы «тело выполнялось» / «ни разу»), `except` и `case`; условия — листья `and`/`or`/`not`; сравнения —
  одиночные `<, <=, >, >=, ==, !=` (цепочки `a < b < c` и `in`/`is` — без реляционных исходов). Номера строк
  и трейсбеки остаются пользовательскими (`File "main.py"`). Если код не удалось инструментировать, программа
  запускается без покрытия, а панель показывает причину.

## Стримы (Stream API)
Цепочки `xs.stream().filter(…).map(…).collect(…)` раскладываются на графе потока управления (CFG) в конвейер.
- **Конвейер на графе:** узлы «Стрим» — источник (`stream-source`, вместе с префиксом `List<T> r = `/`return `),
  по узлу на каждую операцию (`stream-op`) и терминальная операция (`stream-terminal`). Раскладываются цепочки,
  которые занимают целый инициализатор локальной переменной (только при одном деклараторе: `List<T> r = …;`, не
  `int a = 0, b = …;`), целый оператор-выражение, правую часть
  присваивания или `return`; цепочки внутри аргументов, условий и лямбд остаются одним узлом.
- **Правка шага:** метка любого узла конвейера редактируется как обычная — код метода перегенерируется с новым шагом
  (`filter(x -> x >= 0)`). Пустая метка шага удаляет его; вставка всей цепочки в узел-источник её не дублирует;
  если в узле-источнике переписать префикс (`List<T> q = …`, `q = …`, `return …`), новый префикс заменяет старый.
- **Big O:** проход по стриму — O(n) на каждый шаг, `sorted` — O(n log n), `flatMap` умножает на размер внутреннего
  потока, стрим в цикле умножается на цикл; `limit`/`findFirst`/`anyMatch` оценку не снижают.
- **Дефекты и советы:** повторный стрим по той же коллекции внутри цикла по ней (O(n²)); `collect(toList()).size()`
  → `count()`; `filter(…).findFirst().isPresent()` → `anyMatch(…)`; `sorted(…).findFirst()` → `min`/`max`;
  `forEach`, изменяющий внешнюю коллекцию; цикл, который можно заменить стримом. При выключенном ИИ советы берутся
  из `ai/static_tips.py`. Демо — пример `Streams.java`.
- **Ограничения:** правила для стримов работают только на раскладываемых цепочках (кроме «цикл → стрим» — оно
  смотрит на сам цикл); возможны ложные срабатывания «forEach изменяет внешнюю коллекцию» для локальной коллекции
  внутри блока лямбды.

## Ограничения
- Многопользовательский режим без логина: сессия на каждую вкладку браузера через заголовок `X-Session-Id` (UUID; сессии хранятся в LRU-кэше сервера до 200 штук, неактивные >1 ч удаляются; лимит 30 новых сессий на IP за 10 минут). За nginx настоящий IP передаётся в `X-Forwarded-For`.
- Проект хранится локально в браузере (IndexedDB `jb.project.v1`): все изменения пользователя, новые файлы и папки живут только в его браузере, не затрагивая серверные примеры. При сбое хранилища/приватном режиме — прозрачный откат в память с предупреждением.
- Граф с минимальным числом пересечений: раскладка ELK (`elkjs` layered) с ортогональной маршрутизацией рёбер, обходом узлов и отдельными портами для обратных стрелок циклов. Кнопка «Граф» в шапке позволяет скрывать граф (по умолчанию скрыт, скрывается при смене языка) с автоматическим растягиванием редактора.
- Парсер Java — форк `javalang` в `backend/javalang/` (MIT), синтаксис до Java 17. Не поддерживаются конструкции
  Java 21 (`case Type t ->` и record-образцы в `switch`). Switch-выражение, анонимный класс, лямбда с блоком
  и локальный класс показываются в CFG одним узлом с исходным текстом. Record и sealed-типы компилируются только
  JDK 16/17+ (в Docker — JDK 17). Парсер Python — стандартный `ast` (Python 3.11+).
- Декомпозиция Java переносит `static`-методы в классы по префиксам имён, вложенные классы/record/enum — в свои
  файлы, а замкнутую группу полей объекта с методами, которые одни их используют, выделяет в класс-компонент
  (Extract Class): монолит держит его экземпляр и делегирует ему с прежними сигнатурами. В Python функции и
  классы переносятся в модули.
- Правка узла графа поддерживает текст операторов, условий циклов/if, return/throw, catch/except-параметры и шаги
  стрима Java (источник, операции, терминальная операция).
- Запуск: `JAVA_SANDBOX_MODE=subprocess` (по умолчанию, таймаут 10 с; Java — `-Xmx256m`, в консоли `-Xmx100m`; Python — лимит адресного
  пространства 100 МБ) или `docker` (изоляция без сети, контейнер 256 МБ, Java — `-Xmx256m` и в консоли; и Java, и
  Python запускаются в образе песочницы). В docker при подсчёте покрытия `--ulimit fsize` ограничивает размер и тех
  файлов, которые пишет сама программа.
- Сессия интерактивной консоли длится не больше 10 с (`interactive.MAX_SESSION_SEC`), включая ожидание ввода для
  `input()`/`Scanner`: по истечении запуск завершается с «Timeout».
  Дочерний процесс получает только минимальное окружение (`PATH`, `LANG`…), ключи `GEMINI_*` и прокси ему не видны.

## AI-подсказки (Gemini, опционально)
```bash
cp backend/.env.example backend/.env   # LLM_ENABLED=true, ключи и прокси — см. комментарии в файле
```
- **«Объяснить с ИИ»** у дефекта — объяснение и исправленный фрагмент (если применим); иконка «Совет ИИ по разбиению»
  во вкладке «Декомпозиция».
- **Диагностика** всегда отражает текущий код: подсказка, чей фрагмент исчез, скрывается сразу; авто-ревью отменяет
  запрос при новой правке; ответ «Объяснить»/«Исправить» не отбрасывается, но его правка скрывается, как только её
  фрагмент пропадает из кода. Ошибки `javac` с номерами строк — в разделе «Синтаксис и компиляция», у каждой кнопка
  «✨ Исправить с ИИ» (при включённом ИИ). Если `javac` отработал, показываются только его ошибки (он главнее
  парсера); ошибки парсера видны лишь когда `javac` не запускался, и без кнопки ИИ.
- **Авто-ИИ:** через 5 секунд после последней правки кода показывается плашка «ИИ-модель смотрит, как улучшить ваш
  код…», затем в шапке появляется кнопка «✨ N идей» → панель с советами (клик по совету — переход к строке).
  Новая правка сбрасывает таймер и отменяет запрос. Отключается галочкой «Авто-ИИ» (запоминается в браузере).
- **Ключи:** `GEMINI_API_KEY=k1,k2,k3` (список через запятую); `GEMINI_KEYS_COUNT` — использовать только первые N.
- **Прокси:** `GEMINI_PROXIES=ip:login:password,ip:port:login:password,…` — запросы к Gemini идут только через них
  (случайный прокси на каждую попытку); протокол — `GEMINI_PROXY_SCHEME` (по умолчанию `auto`: порт «обнюхивается» без отправки пароля — ответ `0x05` значит SOCKS5, `HTTP/…` значит HTTP — и найденный протокол запоминается; если порт молчит, на следующих попытках перебираются `http` → `socks5` → `https`; можно зафиксировать `http`/`https`/`socks5`/`socks5h` или указать схему прямо в записи `socks5://…`); для записей без порта —
  `GEMINI_PROXY_PORT`. Без прокси соединение прямое.
- **Ретраи:** при ошибке (сеть, 4xx/5xx, пустой или неразборчивый ответ) запрос повторяется с другим случайным ключом
  и прокси; модель облегчается (`GEMINI_MODEL` → `gemini-2.5-flash` → `gemini-2.5-flash-lite`, список —
  `GEMINI_FALLBACK_MODELS`); пауза между попытками 2, 4, 6… с. Число попыток — `GEMINI_MAX_RETRIES` (по умолчанию
  число ключей, максимум 5). Когда ключи кончились, список начинается заново.
- **Применимые правки:** модель возвращает пару «фрагмент → замена» (+ недостающие `import`). Сервер находит фрагмент
  в коде (отступы не важны, место должно быть однозначным), расставляет отступы и проверяет результат (синтаксис +
  `javac` для Java, парсер + `compile()` для Python; ничего не запускается). Пользователю показывается только правка, которая не добавляет новых ошибок
  относительно текущего кода; для «✨ Исправить с ИИ» она также должна устранять целевую ошибку. Невалидные правки
  и советы без правки скрываются; если все правки невалидны, модель дважды переспрашивают с текстом ошибок.
  Кнопка **«Применить»** показывает diff; при применении проверка повторяется на актуальном коде (если вы успели
  править — фрагмент ищется заново). Ctrl+Z отменяет правку; «Проверить поведение» сравнивает вывод с исходным
  кодом (с вашим вводом из консоли).
- **Big O «было → станет»:** у каждой применимой правки ИИ сервер считает сложность затронутых методов до и после
  (`bigoBefore`/`bigoAfter`; затронут метод, чьи строки задеты правкой или чья оценка изменилась, например `main`,
  вызывающий исправленный метод). В строке «Сложность методов · Big O» и в просмотре правки показывается
  `O(n²) → O(n) · ~1000× быстрее`. Ускорение считается только по формуле, без запуска: `f_до(n) / f_после(n)` при
  n ≈ 1000 (тултип «при n ≈ 1000»), `log` по основанию 2; значение округляется до ближайшего (по логарифму) из
  2, 5, 10, 100, 1000, 10000, 100000, 1000000, всё выше — «>1000000×». Если несколько правок применимы одновременно,
  «после ИИ» — сложность после всех: непересекающиеся применяются по очереди, при пересечении строк берётся лучшая
  одиночная (`POST /api/ai/bigo-combined`, ИИ не вызывается). При той же сложности бейдж скрыт целиком (и стрелка, и ускорение); если
  стало хуже — красный бейдж «~N× медленнее»; при неизвестной сложности (`O(?)`) стрелки и ускорения нет.
- **Ожидаемый эффект без ИИ:** у дефектов со сложностью правило задаёт оценку после рекомендации (`bigOAfter`:
  вложенный цикл глубины k → O(n^(k-1)), экспоненциальная рекурсия → O(n), стрим в цикле по той же коллекции →
  O(n), `sorted().findFirst()` → O(n), Python: `in list` в цикле, конкатенация строки в цикле → O(n)). Карточка
  дефекта показывает «Ожидаемый эффект: O(n²) → O(n) · ~1000× быстрее»; строка метода в «Сложность методов» берёт
  эту оценку, если метод имеет такую сложность только из-за дефектов с известным эффектом и правок ИИ нет.
- Без LLM кнопка «Объяснить с ИИ» даёт статические советы из базы паттернов, авто-ревью молчит. Все вызовы асинхронные.
- Диагностика: `cd backend && python check_llm.py` — по одному запросу через каждый прокси и напрямую (запускайте там,
  где будет работать приложение; в Docker: `docker compose exec backend python check_llm.py`). Если на компьютере
  включён VPN в режиме TUN, он перехватывает соединения и прокси с этой машины не проверить.
- SOCKS5: при `auto` определяется сам; принудительно — `GEMINI_PROXY_SCHEME=socks5` (`socksio` уже в `requirements.txt`).
- Локальная альтернатива: `LLM_PROVIDER=ollama`.
- Ключи и логины прокси не попадают в ответы API и логи (в логах — только `host:port` и последние 4 символа ключа).
- **Промпты по языкам:** `backend/ai/prompts/java/*.txt` и `backend/ai/prompts/python/*.txt` (язык берётся из
  запроса или `SESSION.language`); если для языка файла нет, используется вариант из `prompts/java/`.

## Развёртывание за прокси
- Лимит новых сессий (30 за 10 минут) считается по IP клиента. nginx (`frontend/nginx.conf`) — внешний прокси и
  **перезаписывает** `X-Forwarded-For` настоящим адресом клиента (`$remote_addr`), а не дописывает к присланному.
  uvicorn доверяет этим заголовкам только от адресов из `FORWARDED_ALLOW_IPS` (IP или CIDR через запятую; по умолчанию
  `127.0.0.1`). В `docker-compose.yml` доверяется только контейнер nginx: сеть `jbnet` (`JB_SUBNET`, по умолчанию
  `172.30.57.0/24`), nginx получает фиксированный адрес `JB_NGINX_IP` (по умолчанию `172.30.57.10`), и
  `FORWARDED_ALLOW_IPS` по умолчанию равен ему. Меняйте `JB_NGINX_IP` и `FORWARDED_ALLOW_IPS` вместе.
- `FORWARDED_ALLOW_IPS` в `environment:` перекрывает значение из `backend/.env`, поэтому задавайте его в оболочке или в
  корневом `.env`.
- Не ставьте `*`, если порт бэкенда доступен напрямую: иначе клиент сможет подделать свой IP.

## Безопасность
- Сервис выполняет присланный код. В `subprocess`-режиме это **не песочница** — только для локальной разработки;
  для доступа извне используйте `JAVA_SANDBOX_MODE=docker`. Авторизации нет; у каждой вкладки браузера своя сессия (`X-Session-Id`).
- Вызовы API и WebSocket принимаются только с разрешённых origin (`ALLOWED_ORIGINS`).
